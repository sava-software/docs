## Solana Accounts

[SolanaAccounts](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/accounts/SolanaAccounts.java)
provides the native/builtin program IDs, common SPL program IDs, and sysvar addresses,
each with pre-constructed read/invoked `AccountMeta` variants.

```java
var accounts = SolanaAccounts.MAIN_NET;
var tokenProgram = accounts.invokedTokenProgram();
var clock = accounts.readClockSysVar();
```

For a fork or custom deployment, use
[SolanaAccountsBuilder](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/accounts/SolanaAccountsBuilder.java)
and override only the addresses which differ; every field defaults to its main-net value.

```java
var accounts = SolanaAccountsBuilder.builder()
    .tokenProgram("<forkedTokenProgram>")
    .create();
```

## Token-2022 Extensions

[Token2022](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/accounts/token/Token2022.java)
and [Token2022Account](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/accounts/token/Token2022Account.java)
parse known [Token-2022 extensions](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/accounts/token/extensions)
into a sealed type hierarchy. Unrecognized type IDs in well-formed TLV data are retained
as `UnknownTokenExtension` with their on-chain type value and raw data. Truncated TLV
values, mismatched fixed-size extension lengths, and duplicate extension IDs are rejected.

`ordinal()` exposes the stable on-chain type ID. In 25.11.0, use `tokenExtensions()` and
concrete types in place of the removed enum/map accessors; see the
[Token-2022 migration notes](/releases/25.11.0#token-2022-extensions).

```java
var token2022 = Token2022.read(mintAddress, accountData);
for (var extension : token2022.tokenExtensions()) {
  switch (extension) {
    case TransferFeeConfig(_, _, _, _, TransferFee(_, long maxFee, int feeBasisPoints)) ->
        System.out.format("Transfer fee: %d bps, max %d%n", feeBasisPoints, maxFee);
    case TokenMetadata metadata -> System.out.println(metadata.name());
    case UnknownTokenExtension(int type, byte[] data) ->
        System.out.println("New extension released, type " + type);
    default -> {
    }
  }
}
```

## Private Key Parsing

<Info>
  `JsonIterator` is provided by the transitive
  [json-iterator](https://github.com/comodal/json-iterator) dependency of `sava-rpc`.
</Info>

### Usage

```java
var jsonConfig = "";
var ji = JsonIterator.parse(jsonConfig);
var signer = PrivateKeyEncoding.fromJsonPrivateKey(ji);
```

### JSON Configuration

If the base58 encoded public key is configured via `pubKey` it will be used to further validate the public key derived
from the private key.

#### Solana CLI Key Pair JSON Array

By default, if only an array is configured, the assumption is that it is a key pair generated by the Solana CLI.

```
[1,2,3, ... ,42]
```

#### JSON Array

```json
{
  "pubKey": "<BASE58_ENCODED_PUBLIC_KEY>",
  "encoding": "jsonKeyPairArray",
  "secret": []
}
```

#### Key Pair

Encoded 64 byte private/public key pair. Derived public key will be validated.

* base64KeyPair
* base58KeyPair

```json
{
  "pubKey": "<BASE58_ENCODED_PUBLIC_KEY>",
  "encoding": "base64KeyPair",
  "secret": "asdf=="
}
```

#### Private Key Only

Encoded 32 byte private key.

* base64PrivateKey
* base58PrivateKey

```json
{
  "pubKey": "<BASE58_ENCODED_PUBLIC_KEY>",
  "encoding": "base64PrivateKey",
  "secret": "asdf=="
}
```

## Transaction Deserialization

The [TransactionSkeleton](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/tx/TransactionSkeleton.java)
interface provides a lightweight view over transaction data. Allowing for partial introspection or complete reconstruction of
a [Transaction](https://github.com/sava-software/sava/tree/main/sava-core/src/main/java/software/sava/core/tx/Transaction.java).

### Legacy

```java
byte[] legacyTransactionData = ...;
var skeleton = TransactionSkeleton.deserializeSkeleton(legacyTransactionData);
AccountMeta[] accounts = skeleton.parseAccounts();
Instruction[] instructions = skeleton.parseLegacyInstructions();
Transaction transaction = skeleton.createTransaction();
```

<a id="versioned"></a>

### v0

```java
byte[] v0TransactionData = ...;
var skeleton = TransactionSkeleton.deserializeSkeleton(v0TransactionData);
var instructionsWithoutTableAccounts = skeleton.parseInstructionsWithoutTableAccounts();

PublicKey[] tableAccounts =  skeleton.lookupTableAccounts();
// ... Fetch table accounts (See RPC) ...
AddressLookupTable lookupTable = ...;
AccountMeta[] accounts = skeleton.parseAccounts(lookupTable);
Instruction[] instructions = skeleton.parseInstructions(accounts);
Transaction transaction = skeleton.createTransaction(instructions, lookupTable);
```

### v1

The same deserializer recognizes v1. All v1 accounts are carried directly in the
message, so no address lookup tables need to be fetched.

```java
byte[] v1TransactionData = ...;
var skeleton = TransactionSkeleton.deserializeSkeleton(v1TransactionData);
int version = skeleton.version(); // 1
AccountMeta[] accounts = skeleton.parseAccounts();
Instruction[] instructions = skeleton.parseInstructions(accounts);
long priorityFeeLamports = skeleton.priorityFeeLamports();
int computeUnitLimit = skeleton.computeUnitLimit();
```

Deserialization reads the wire structure; it does not establish signature validity
or whether a transaction would execute successfully on a cluster.
